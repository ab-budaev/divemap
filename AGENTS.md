# Dive Map — контекст для агентских сессий

> Карта мест погружений: персональный дайвлог с интерактивной картой.
> Проект для GitHub-профиля (демонстрация инженерных навыков) и песочница технологий.
> Этот файл — единственный источник правды о продукте. При расхождении с кодом — уточнить у владельца, не додумывать.

## Цель MVP

Пользователь (один, без регистрации) добавляет места погружений кликом по карте, ведёт журнал погружений по каждому месту, прикрепляет фото, видит всё на карте и в списке, редактирует и удаляет. Приложение задеплоено и доступно по публичной ссылке.

## Модель данных

Две сущности:

**Spot (место)**

- `name` — обязательное
- `coordinates` (lat/lng) — задаются только кликом по карте
- `description` — опционально
- фото — общая галерея спота, до 10 файлов за загрузку

**Dive (погружение)** — привязано к Spot

- `date` — обязательное, по умолчанию сегодня
- `depth`, `duration`, `visibility`, `temperature` — опционально
- `rating` — лайк/дизлайк (бинарный, не шкала)

Связь: один Spot → много Dive. Удаление Spot каскадно удаляет его Dive и фото (с подтверждением в UI).

## User flow (утверждён)

3 экрана, карточка и формы — панели поверх карты, отдельных страниц нет.

1. **Карта (главная)** — маркеры всех мест; сайдбар со списком мест (название + дата последнего погружения). Клик по маркеру/пункту списка → карточка места. Клик по пустой точке карты → форма создания места (координаты из клика). Пустое состояние — подсказка «Кликните по карте, чтобы добавить первое место».
2. **Форма места** — название (обязательно), описание, перестановка маркера повторным кликом, загрузка фото (до 10). Сохранить / Отмена. В режиме редактирования — «Удалить» с подтверждением.
3. **Карточка места** — название, описание, фотогалерея, журнал погружений по датам. «Добавить погружение» (дата обязательна, остальное опционально). Редактирование/удаление каждого погружения. «Редактировать место».

## Критерии приёмки MVP

**Функциональные:**

- [ ] Место добавляется кликом по карте, достаточно только названия
- [ ] К месту загружаются до 10 фото, видны в карточке
- [ ] Погружение добавляется к месту, достаточно только даты
- [ ] Любые поля места и погружения редактируются
- [ ] Погружение удаляется; место удаляется с подтверждением (каскадно)
- [ ] Все места видны маркерами на карте и списком в сайдбаре
- [ ] Данные переживают перезагрузку страницы и рестарта сервера (реальное хранение, не mock)

**Нефункциональные:**

- [ ] Публичная ссылка на приложение
- [ ] Корректная работа на десктопе (мобильная вёрстка — nice to have, не блокер)
- [ ] README: описание проекта, локальный запуск, скриншот

## Явно НЕ в MVP — не реализовывать без запроса

- Регистрация, логин, мультипользовательность
- Поиск и фильтры по местам
- Мобильная адаптация
- Статистика, импорт GPS-треков, социальные функции
- Ручной ввод координат (широта/долгота текстом)

## Принципы для агента

- Минимум обязательных полей: название места и дата погружения — всё остальное опционально.
- Не расширять скоуп: новые сущности, поля и фичи — только после явного запроса владельца.
- Хранение данных — настоящее (БД + файловое хранилище для фото), не localStorage и не mock.
- Вопросы по продукту (скоуп, сценарии) выносятся владельцу до реализации, не решаются молча.

## Технические решения (фундамент)

- Монорепо: `backend/` (FastAPI) + `frontend/` (React + TypeScript, Vite); бэкенд отдаёт собранный фронтенд как статику
- Backend: FastAPI + SQLAlchemy 2.0 + Alembic + pydantic-settings
- БД: PostgreSQL (сервис в docker-compose)
- Деплой: свой VPS, Docker Compose (app + db), Caddy как reverse proxy с автоматическим TLS
- Домен: появится позже, не блокирует старт

## Этапы (куски MVP)

1. Фундамент — репо, стек, БД, каркас фронта, деплой, публичная ссылка
2. Карта + Spot — клик по карте -> создание, маркеры, форма, карточка, сайдбар, удаление с подтверждением
3. Журнал погружений — CRUD дайвов, дата по умолчанию сегодня, лайк/дизлайк
4. Фото — загрузка до 10 за раз, галерея, каскад с удалением спота
5. Полировка — критерии приёмки, README, скриншоты
