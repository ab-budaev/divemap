# tech/general Specification

## Purpose

Проверка соответствия коммит-сообщений формату [conventional commits](https://www.conventionalcommits.org/ru/v1.0.0/): локально — git-хуком `commit-msg`, который отклоняет коммит до его создания, и в CI — проверкой сообщений коммитов в push и pull request.

## Requirements

### Requirement: Локальная проверка коммит-сообщений git-хуком

Система ДОЛЖНА (MUST) отклонять создание коммита локально, если его сообщение не соответствует формату conventional commits. Проверка ДОЛЖНА (MUST) выполняться git-хуком `commit-msg` (фреймворк pre-commit, хук conventional-pre-commit); конфигурация хранится в `.pre-commit-config.yaml` в корне репозитория. При отклонении система ДОЛЖНА (MUST) выводить ошибку, указывающую на нарушение формата.

#### Scenario: [P0] Коммит с корректным сообщением создаётся

- **GIVEN** разработчик установил git-хуки и находится в репозитории с незакоммиченными изменениями
- **WHEN** он выполняет `git commit -m "feat: add dive journal entry"`
- **THEN** коммит создаётся успешно, проверка проходит без ошибок

#### Scenario: [P0] Коммит с некорректным сообщением отклоняется

- **GIVEN** разработчик установил git-хуки и находится в репозитории с незакоммиченными изменениями
- **WHEN** он выполняет `git commit -m "добавил запись в журнал"`
- **THEN** коммит НЕ создаётся, в выводе отображается ошибка о несоответствии формату conventional commits

#### Scenario: [P1] Отклонённый коммит можно исправить повторной попыткой

- **GIVEN** попытка коммита была отклонена хуком из-за неверного формата сообщения
- **WHEN** разработчик повторяет `git commit` с сообщением в формате conventional commits
- **THEN** коммит создаётся успешно

### Requirement: Установка git-хуков одной командой

Система ДОЛЖНА (MUST) предоставлять цель в корневом `Makefile`, которая устанавливает git-хуки (включая `commit-msg`) в локальный репозиторий одной командой. Команда ДОЛЖНА (MUST) быть идемпотентной: повторный запуск не должен приводить к ошибке или дублированию хуков.

#### Scenario: [P0] Установка хуков после клонирования репозитория

- **GIVEN** разработчик склонировал репозиторий и установил инструмент pre-commit
- **WHEN** он выполняет make-цель установки хуков
- **THEN** git-хук `commit-msg` активен: последующий коммит с некорректным сообщением отклоняется

#### Scenario: [P2] Повторная установка хуков

- **GIVEN** git-хуки уже установлены в репозитории
- **WHEN** разработчик повторно выполняет make-цель установки хуков
- **THEN** команда завершается успешно, хуки остаются в рабочем состоянии

### Requirement: Проверка коммит-сообщений в CI

Система ДОЛЖНА (MUST) проверять сообщения коммитов в GitHub Actions при push и pull request: каждое коммит-сообщение в диапазоне события ДОЛЖНО (MUST) соответствовать формату conventional commits, при нарушении job ДОЛЖЕН (MUST) завершаться с ошибкой.

#### Scenario: [P0] Push с корректными коммитами проходит проверку

- **GIVEN** разработчик отправил push, все коммиты которого соответствуют conventional commits
- **WHEN** запускается workflow проверки коммитов в GitHub Actions
- **THEN** job завершается успешно

#### Scenario: [P0] Push с некорректным коммитом не проходит проверку

- **GIVEN** разработчик отправил push, содержащий коммит с сообщением «fix stuff»
- **WHEN** запускается workflow проверки коммитов в GitHub Actions
- **THEN** job завершается с ошибкой, в логе видно, какое сообщение нарушает формат

#### Scenario: [P1] Pull request с некорректным коммитом не проходит проверку

- **GIVEN** открыт pull request, содержащий коммит с сообщением не в формате conventional commits
- **WHEN** запускается workflow проверки коммитов в GitHub Actions
- **THEN** job завершается с ошибкой, статус проверки в PR отображается как неуспешный

### Requirement: Документирование процесса установки хуков

`CONTRIBUTING.md` ДОЛЖЕН (MUST) содержать рядом с соглашением о conventional commits инструкцию по установке git-хуков: команду установки и требование установить инструмент pre-commit.

#### Scenario: [P1] Новый разработчик настраивает репозиторий по документации

- **GIVEN** разработчик склонировал репозиторий
- **WHEN** он открывает `CONTRIBUTING.md`, раздел «Соглашения по коммитам»
- **THEN** он видит инструкцию по установке хуков и может воспроизвести настройку без обращения к другим источникам
