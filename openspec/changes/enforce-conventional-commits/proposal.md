# Proposal

## Мотивация

`CONTRIBUTING.md` уже объявляет, что проект использует [conventional commits](https://www.conventionalcommits.org/ru/v1.0.0/), но соглашение ничем не подкреплено: в репозитории нет ни локальных git-хуков, ни проверок в CI. Формат сообщений соблюдается только «на честном слове», и отклонения замечаются постфактум, когда история уже заполнена.

Проект позиционируется как витрина инженерных навыков для GitHub-профиля — аккуратная и единообразная история коммитов здесь часть продукта. Кроме того, единый формат сообщений — фундамент для будущей автоматизации (генерация changelog, определение версии по типам коммитов).

## Пользовательские сценарии

Я как разработчик (владелец проекта):

- хочу, чтобы коммит с сообщением не в формате conventional commits отклонялся локально до создания коммита, чтобы ошибочное сообщение нельзя было закоммитить случайно;
- хочу получать понятное сообщение об ошибке с указанием, что именно не так в формате, чтобы быстро исправить сообщение;
- хочу, чтобы CI проверял сообщения коммитов в push/PR, чтобы история в удалённом репозитории оставалась чистой, даже если локальный хук не установлен или обойдён (`--no-verify`);
- хочу, чтобы установка хуков происходила одной командой (`make`), чтобы на новой машине настройка занимала минимум времени.

## Что меняется

Добавлено:

- Локальная автоматическая проверка формата коммит-сообщений через git-хук `commit-msg` (фреймворк pre-commit, хук conventional-pre-commit).
- Проверка формата коммит-сообщений в CI (GitHub Actions) для push и pull request.
- Make-цель для установки git-хуков на машине разработчика.
- Конфигурация pre-commit в корне репозитория.

Изменено:

- `CONTRIBUTING.md` — инструкция по установке хуков рядом с уже объявленным соглашением о коммитах.

Удалено:

- —

Явно отложено за пределы этого изменения:

- Генерация changelog и автоматическое версионирование по типам коммитов.
- Проверка других стадий pre-commit (линтеры, форматтеры) — в этом изменении настраивается только `commit-msg`.
- Переписывание существующей истории коммитов под conventional commits.

- —

## Влияние

- Код приложения (backend/frontend) не затрагивается — меняется только инфраструктура разработки.
- Новые файлы: `.pre-commit-config.yaml` в корне, workflow GitHub Actions для проверки коммитов.
- Новая dev-зависимость: `pre-commit` (устанавливается как инструмент, не входит в зависимости приложения).
- Make-цель `hooks` (или аналогичная) в корневом `Makefile`.
- Разработчику потребуется один раз выполнить установку хуков после клонирования; без этого локальная проверка не активна (страховка — CI).
