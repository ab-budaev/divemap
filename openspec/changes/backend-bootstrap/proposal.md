# Proposal

## Мотивация

Проект divemap — персональный дайвлог с интерактивной картой мест погружений. Репозиторий содержит только документацию: нет ни кода, ни инфраструктуры, ни работающего окружения. Без фундамента невозможно начать функциональные этапы (карта и места, журнал погружений, фото). Это изменение создаёт минимальный локальный фундамент, на котором строятся все последующие этапы.

Полноценный bootstrap (деплой на VPS, reverse proxy, публичная ссылка) осознанно откладывается: сначала нужен работающий локальный контур для разработки.

## Пользовательские сценарии

Я как разработчик:

- хочу одной командой поднять локальное окружение (приложение + база данных).
- хочу, чтобы данные не пропадали при перезапуске и пересоздании контейнеров.
- хочу иметь каркас бэкенда со слоистой DDD-структурой, готовый к этапам 2–4 без переделки инфраструктуры.
- хочу, чтобы сервис отчитывался о своём состоянии через health-check эндпоинт.

## Что меняется

Добавлено:

- Backend-каркас, сгенерированный из шаблона репозитория `git@github.com:ab-budaev/python-template.git` и доработанный под требования спеки
- Локальное окружение: приложение и база данных поднимаются одной командой, данные переживают перезапуск
- Служебный health-check эндпоинт сервиса
- Документация по локальному запуску

Изменено: только README (запуск и описание проекта).

Удалено: ничего.

Явно отложено за пределы этого изменения: деплой на VPS, Caddy/reverse proxy, домен и TLS, публичная ссылка, объектное хранилище Minio (добавится вместе с этапом «Фото»).

## Возможности

### Новые возможности

- `tech/backend`: операционное поведение бэкенд-сервиса — health-check эндпоинт, запуск локального окружения одной командой с сохранностью данных между перезапусками.

### Изменённые возможности

Нет: существующих спецификаций нет, поведение не меняется.

## Влияние

- Появляется локальное окружение разработки, готовое к этапам 2–4
- Эксплуатационные зависимости ограничены локальным Docker Compose: приложение + PostgreSQL
- Деплой, публичная ссылка, домен и Minio остаются открытыми для последующих изменений
