# Proposal

## Мотивация

Сейчас места погружений (споты) на карте — это хардкод во фронтенде: массив `demoSpots` в `frontend/src/features/map/spots.ts`. Это нарушает базовый принцип MVP: данные должны храниться в PostgreSQL и переживать перезагрузку страницы и рестарт сервера. Пока точки живут в коде, их нельзя ни изменить, ни дополнить без правки фронтенда и повторной сборки.

Это изменение — первый шаг этапа «Карта + Spot»: переносим демо-точки в базу данных, добавляем API-ручку для их получения и учим фронтенд загружать споты через API вместо хардкода. Создание и редактирование спотов через UI в этот change не входит.

## Пользовательские сценарии

Я как пользователь:

- хочу видеть на карте те же места погружений, что и раньше, но чтобы они хранились в базе данных, чтобы данные не зависели от кода фронтенда.
- хочу видеть понятное состояние загрузки и ошибки, если список мест не удалось получить, чтобы понимать, что происходит.

Я как разработчик:

- хочу получать список спотов через REST API, чтобы фронтенд и бэкенд были развязаны и данные можно было менять без пересборки.

## Что меняется

Добавлено:

- Таблица `spots` в PostgreSQL (миграция Alembic) с полями: `id` (UUID), `name`, `description` (nullable), `lat`, `lng`, `created_at`, `updated_at`.
- Сиды: три текущие демо-точки переносятся в таблицу `spots` в той же миграции.
- REST-эндпоинт `GET /spots`, возвращающий список всех спотов (id, name, description, координаты).
- Доменная сущность `Spot`, протокол репозитория, SQLAlchemy-модель и репозиторий, use-case получения списка спотов — по существующей DDD-структуре backend (`domain/`, `application/`, `infrastructure/`, `api/`).
- Клиентский модуль `frontend/src/api/spots.ts` для запроса списка спотов.

Изменено:

- `MapScreen` загружает споты через API при монтировании вместо импорта хардкода `demoSpots`; пока идёт загрузка — карта показывает пустой слой маркеров, при ошибке — сообщение об ошибке с возможностью повторить запрос.

Удалено:

- Хардкод `demoSpots` и тип `DemoSpot` из `frontend/src/features/map/spots.ts` (файл удаляется, тип `Spot` переезжает в API-слой).

Явно отложено за пределы этого изменения:

- Создание, редактирование и удаление спотов (этап «Карта + Spot»).
- Пагинация, фильтрация и поиск по спотам.
- Сущность Dive и фото спотов.

## Возможности

### Новые возможности

- `map-spots`: хранение мест погружений в БД и выдача их списка через REST API для отображения на карте.

### Изменённые возможности

## Влияние

- **БД:** новая миграция Alembic создаёт таблицу `spots` и наполняет её тремя демо-записями. Откат миграции удаляет таблицу.
- **Backend:** новые модули `domain/spots.py`, `application/spots.py`, `infrastructure/spots.py`, `api/routers/spots.py`; роутер регистрируется в `api/app.py`, зависимость — в `api/dependencies.py`.
- **Frontend:** `MapScreen` переходит на данные из API; удаляется `features/map/spots.ts`; добавляется `api/spots.ts`. Панель `SpotPanel` продолжает работать с теми же данными, тип меняется.
- **Пользователи:** внешне поведение карты не меняется — те же три маркера на тех же местах; появляются состояния загрузки/ошибки списка мест.
