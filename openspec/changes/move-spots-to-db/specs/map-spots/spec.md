# Spec Delta

## Purpose

Хранение мест погружений (спотов) в PostgreSQL и выдача их списка через REST API, чтобы карта во фронтенде отображала реальные данные из базы, а не хардкод.

## ADDED Requirements

### Requirement: Хранение спотов в базе данных

Система ДОЛЖНА (MUST) хранить места погружений в таблице `spots` в PostgreSQL с полями: уникальный идентификатор, название, описание (опционально), широта, долгота, время создания и обновления. Система ДОЛЖНА (MUST) при применении миграции наполнить таблицу тремя демо-точками, которые ранее были захардкожены во фронтенде: «Байкал, Листвянка», «Шарм-эль-Шейх, Рас Умм Сид», «Голубая дыра» — с теми же координатами и описаниями.

#### Scenario: [P0] Миграция создаёт и наполняет таблицу spots

- **GIVEN** база данных без таблицы `spots`
- **WHEN** применяется миграция Alembic
- **THEN** таблица `spots` создана и содержит ровно 3 демо-спота с корректными названиями, описаниями и координатами

#### Scenario: [P1] Откат миграции удаляет таблицу spots

- **GIVEN** применённая миграция с таблицей `spots`
- **WHEN** выполняется downgrade миграции
- **THEN** таблица `spots` удалена из базы данных

### Requirement: API получения списка спотов

Система ДОЛЖНА (MUST) предоставлять эндпоинт `GET /spots`, возвращающий HTTP 200 и JSON-массив всех спотов из базы данных. Каждый элемент массива ДОЛЖЕН (MUST) содержать поля `id`, `name`, `description` (может быть null), `lat`, `lng`. Система НЕ ДОЛЖНА требовать авторизацию для этого эндпоинта.

#### Scenario: [P0] Успешное получение списка спотов

- **GIVEN** в базе данных есть 3 демо-спота
- **WHEN** клиент отправляет `GET /spots`
- **THEN** возвращается HTTP 200 с JSON-массивом из 3 элементов, каждый содержит `id`, `name`, `description`, `lat`, `lng`

#### Scenario: [P1] Пустой список спотов

- **GIVEN** в базе данных нет ни одного спота
- **WHEN** клиент отправляет `GET /spots`
- **THEN** возвращается HTTP 200 с пустым JSON-массивом `[]`

### Requirement: Отображение спотов на карте из API

Система ДОЛЖНА (MUST) загружать список спотов через `GET /spots` при открытии экрана карты и отображать каждый спот маркером в его координатах. Система НЕ ДОЛЖНА содержать хардкод спотов в коде фронтенда. Система ДОЛЖНА (MUST) показывать пользователю сообщение об ошибке с возможностью повторить запрос, если загрузка списка спотов завершилась неудачей.

#### Scenario: [P0] Маркеры отображаются по данным API

- **GIVEN** API `GET /spots` возвращает 3 спота
- **WHEN** пользователь открывает экран карты
- **THEN** на карте отображаются 3 маркера в координатах соответствующих спотов, и клик по маркеру открывает карточку спота с его названием и описанием

#### Scenario: [P1] Ошибка загрузки списка спотов

- **GIVEN** API `GET /spots` недоступен или возвращает ошибку
- **WHEN** пользователь открывает экран карты
- **THEN** отображается карта без маркеров и сообщение об ошибке с кнопкой повторить запрос

#### Scenario: [P2] Повторная загрузка после ошибки

- **GIVEN** отображается сообщение об ошибке загрузки спотов
- **WHEN** пользователь нажимает кнопку повторить запрос и API доступен
- **THEN** сообщение об ошибке скрывается и на карте отображаются маркеры спотов
