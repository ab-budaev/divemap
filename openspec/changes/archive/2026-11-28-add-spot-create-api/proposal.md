# Proposal

## Мотивация

Прошлым изменением (`add-spot-modal`) добавлена модалка создания места, но «Сохранить» — заглушка: данные формы отбрасываются, место в базе не появляется. Это осознанное промежуточное состояние блокирует ключевой сценарий MVP (критерий приёмки: «Место добавляется кликом по карте, достаточно только названия» и «Данные переживают перезагрузку страницы и рестарта сервера»).

Это изменение замыкает сценарий создания места: REST-эндпоинт `POST /spots` на бэкенде и реальная отправка формы из модалки с обновлением карты после сохранения.

## Пользовательские сценарии

Я как пользователь (дайвер, владелец журнала):

- хочу, чтобы заполненная в модалке форма (наименование, координаты, описание) сохраняла место в базе данных, чтобы оно не терялось при перезагрузке страницы.
- хочу сразу после сохранения видеть новое место маркером на карте вместе с остальными, чтобы убедиться, что всё записалось.
- хочу получить понятную ошибку, если сохранение не удалось, и возможность попробовать снова, чтобы не потерять введённые данные.

## Что меняется

Добавлено:

- Эндпоинт `POST /spots` на бэкенде по REST-принципам: принимает JSON `{name, description?, lat, lng}`, создаёт спот в PostgreSQL и возвращает созданный объект с HTTP 201. Валидация входных данных: `name` обязателен (непустой после trim), `lat`/`lng` в допустимых диапазонах.
- Интеграция фронтенда с `POST /spots`: кнопка «Сохранить» в модалке создания отправляет запрос; после успешного ответа список спотов перезапрашивается (инвалидация кэша react-query), новый маркер появляется на карте, окно закрывается.
- Обработка ошибки сохранения в модалке: при сбое запроса форма остаётся открытой с введёнными данными, показывается сообщение об ошибке с возможностью повторить.

Изменено:

- Действие «Сохранить» в модалке создания места: вместо обработчика-заглушки — реальный вызов API. Окно закрывается только после успешного создания.

Удалено:

- Обработчик-заглушка сохранения из `MapScreen` (данные формы больше не отбрасываются).

Явно отложено за пределы этого изменения:

- Загрузка фотографий при создании места (файлы из формы пока не отправляются; хранение фото — этап 4 «Фото» по AGENTS.md, отдельное изменение).
- Редактирование и удаление спота, карточка спота с галереей, журнал погружений.
- Индикация состояния «сохраняем…» сверх базовой блокировки повторной отправки (минимальный UX-блокер двойного клика — в рамках этого изменения).

## Возможности

### Новые возможности

Пусто — обе затрагиваемые capability уже существуют.

### Изменённые возможности

- `map-spots`: добавляется требование «API создания спота» (`POST /spots`): создание места в базе через REST с валидацией входных данных.
- `product/spot-creation`: требование «Действие сохранения (без API)» заменяется на реальное сохранение через API: отправка `POST /spots`, появление нового маркера на карте после успеха, обработка ошибки без потери данных формы.

## Влияние

- **Код бэкенда** (`backend/src/`): домен (`domain/spots.py` — метод `create` в `SpotRepository`), приложение (`application/spots.py` — use-case `CreateSpot`), инфраструктура (`infrastructure/spots.py` — реализация `create`), API (`api/routers/spots.py` — `POST /spots` с моделями запроса/ответа). Миграции БД не нужны: таблица `spots` уже существует.
- **Код фронтенда** (`frontend/src/`): `api/client.ts` (поддержка POST с телом), `api/spots.ts` (`createSpot`), `features/map/MapScreen.tsx` (замена заглушки на mutation с инвалидацией `['spots']`), `features/map/CreateSpotModal.tsx` (состояние отправки и ошибка). Новых зависимостей не требуется — react-query уже используется.
- **API**: добавляется `POST /spots` (201/422). Существующий `GET /spots` не меняется.
- **Данные**: споты, созданные через UI, персистятся в PostgreSQL и переживают перезагрузку страницы и рестарт сервера — закрывается критерий приёмки MVP.
- **Документация**: AGENTS.md не затрагивается.
