# tech/frontend Specification

## Purpose

Capability закрывает базовую эксплуатационную работоспособность фронтенда divemap: каркас на React + TypeScript запускается для разработки одной командой с доступом к локальному API и собирается в отдельный Docker-образ со статикой, независимый от образа бэкенда. Код проверяется линтером, типами и сборкой в CI.

## ADDED Requirements

### Requirement: Запуск всего dev-окружения одной командой из корня репозитория

Система ДОЛЖНА (MUST) предоставлять цель `up` в корневом `Makefile`, которая поднимает всё dev-окружение — бэкенд (через Docker Compose) и dev-сервер фронтенда — одной командой из корня репозитория. Также ДОЛЖНЫ (MUST) существовать отдельные цели для запуска и остановки бэкенда и фронтенда по отдельности. Цели запуска фронтенда ДОЛЖНЫ (MUST) автоматически устанавливать npm-зависимости при их отсутствии.

#### Scenario: [P0] Полный запуск одной командой

- **GIVEN** свежий клон репозитория с установленными Docker и Node.js
- **WHEN** выполняется `make up` в корне репозитория
- **THEN** бэкенд поднят и отвечает на health-check, dev-сервер фронтенда запущен, страница приложения отображает результат health-check

#### Scenario: [P0] Запуск бэкенда и фронтенда по отдельности

- **GIVEN** окружение не запущено
- **WHEN** выполняется отдельная make-цель запуска бэкенда или фронтенда
- **THEN** поднимается только запрошенная часть окружения

#### Scenario: [P1] Автоматическая установка npm-зависимостей

- **GIVEN** каталог `frontend/node_modules` отсутствует
- **WHEN** выполняется make-цель запуска фронтенда
- **THEN** зависимости устанавливаются автоматически, после чего dev-сервер запускается

#### Scenario: [P1] Повторный запуск

- **GIVEN** окружение уже запущено через `make up`
- **WHEN** выполняется `make up` повторно
- **THEN** команда завершается успешно, окружение остаётся в рабочем состоянии

### Requirement: Запуск dev-окружения фронтенда с доступом к локальному API

Система ДОЛЖНА (MUST) предоставлять команду запуска dev-сервера фронтенда с hot-reload. Dev-сервер ДОЛЖЕН (MUST) проксировать запросы к API на локально запущенный бэкенд, чтобы фронтенд работал с реальным API без ручной настройки адресов.

#### Scenario: [P0] Запуск dev-сервера

- **GIVEN** установлены зависимости фронтенда и запущен локальный бэкенд
- **WHEN** выполняется команда запуска dev-сервера фронтенда
- **THEN** dev-сервер поднимается, страница приложения открывается в браузере и отображается каркас приложения

#### Scenario: [P0] Проксирование API-запросов на бэкенд

- **GIVEN** dev-сервер фронтенда и локальный бэкенд запущены
- **WHEN** фронтенд выполняет запрос к API (например, health-check)
- **THEN** запрос доходит до бэкенда и фронтенд получает его ответ без ошибок CORS

#### Scenario: [P1] Hot-reload при изменении кода

- **GIVEN** dev-сервер фронтенда запущен и страница открыта в браузере
- **WHEN** разработчик изменяет исходный файл фронтенда
- **THEN** изменения отображаются в браузере без ручного перезапуска сервера

### Requirement: Production-сборка фронтенда в отдельный Docker-образ

Система ДОЛЖНА (MUST) собирать фронтенд в статические файлы одной командой. Репозиторий ДОЛЖЕН (MUST) содержать `frontend/Dockerfile`, собирающий самодостаточный образ фронтенда (веб-сервер nginx + собранная статика), не зависящий от образа бэкенда. Образ бэкенда НЕ ДОЛЖЕН (MUST NOT) содержать статику фронтенда и не должен её отдавать: бэкенд остаётся чистым API-сервисом.

#### Scenario: [P0] Сборка фронтенда

- **GIVEN** установлены зависимости фронтенда
- **WHEN** выполняется команда production-сборки
- **THEN** создаётся каталог со статическими файлами, сборка завершается без ошибок

#### Scenario: [P0] Образ фронтенда собирается и отдаёт статику

- **GIVEN** собран Docker-образ фронтенда из `frontend/Dockerfile`
- **WHEN** контейнер фронтенда запущен и запрашивается его корневой URL
- **THEN** возвращается HTML-страница собранного фронтенда

#### Scenario: [P1] Образ фронтенда не содержит инструментов сборки

- **GIVEN** собран Docker-образ фронтенда из `frontend/Dockerfile`
- **WHEN** проверяется содержимое итогового образа
- **THEN** в образе присутствуют только веб-сервер и статические файлы: Node.js и зависимости сборки отсутствуют

### Requirement: Независимость образов фронтенда и бэкенда

Образ фронтенда ДОЛЖЕН (MUST) собираться без доступа к коду и образу бэкенда, а образ бэкенда ДОЛЖЕН (MUST) собираться без доступа к коду фронтенда: сборка каждого образа зависит только от своего каталога.

#### Scenario: [P0] Образ фронтенда собирается из каталога frontend/

- **GIVEN** доступен только каталог `frontend/`
- **WHEN** выполняется сборка образа фронтенда
- **THEN** образ собирается успешно без обращения к каталогу `backend/`

#### Scenario: [P1] Образ бэкенда собирается без фронтенда

- **GIVEN** каталог `frontend/` отсутствует
- **WHEN** выполняется сборка образа бэкенда
- **THEN** образ собирается успешно, health-check эндпоинт работает

### Requirement: Проверки качества фронтенд-кода в CI

Система ДОЛЖНА (MUST) проверять фронтенд в CI при push и pull request: линтер, проверка типов TypeScript и production-сборка ДОЛЖНЫ (MUST) завершаться успешно, при нарушении job ДОЛЖЕН (MUST) завершаться с ошибкой.

#### Scenario: [P0] Корректный код проходит проверки

- **GIVEN** разработчик отправил push, фронтенд-код не содержит ошибок линтера и типов
- **WHEN** запускается workflow фронтенд-проверок в CI
- **THEN** линтер, проверка типов и сборка завершаются успешно

#### Scenario: [P0] Ошибка типов не проходит проверку

- **GIVEN** разработчик отправил push, содержащий фронтенд-код с ошибкой типов TypeScript
- **WHEN** запускается workflow фронтенд-проверок в CI
- **THEN** job завершается с ошибкой, в логе видно описание ошибки типов

### Requirement: Документирование запуска фронтенда

README ДОЛЖЕН (MUST) содержать инструкцию по запуску фронтенда для разработки: установку зависимостей, запуск dev-сервера и production-сборку, а также описание структуры каталога `frontend/`.

#### Scenario: [P1] Разработчик запускает фронтенд по документации

- **GIVEN** разработчик склонировал репозиторий
- **WHEN** он следует инструкции запуска фронтенда из README
- **THEN** dev-сервер запускается без обращения к другим источникам
